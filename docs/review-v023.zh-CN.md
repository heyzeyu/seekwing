# v0.2.3 再次复查

日期：2026-10-20。基线：SeekWing `79742fe`（v0.2.2）。重点检查跨进程协作、异常文件写入、并发幂等和较多历史记录时的行为。

## 复现和修复

1. **控制文件可能在写完前被读取**：旧版先创建可见的 `.json` 文件，再写入内容。暂停在文件打开后，任务所有者会尝试解析空文件并删除它，取消或权限选择因此可能丢失。现在先写私有临时文件，再原子重命名发布；未完成的写入不可见，失败写入会清理临时文件且不投递命令。
2. **并发幂等竞争会产生多余失败记录**：另一进程在首次查询之后取得相同 key 时，原请求可能因赢家记录尚未落盘或参数冲突而失败。旧逻辑仍把失败的竞争者写成一个新任务。现在区分容量占位和实际取得提交资格，未取得资格的请求不写入任务记录、不执行指令；已有 key 的结果不确定时仍明确失败并要求核对，不自动重放。
3. **JSON 转义会绕过已知凭据值匹配**：带引号、反斜杠和换行的合成凭据在普通日志里可以被过滤，但序列化后的任务记录和 MCP 输出中仍可能出现。现在补齐原始值及一到两层 JSON 转义形式的匹配，覆盖任务记录和嵌套原生工具 JSON；验证脱敏后内容仍可正确解析。测试仅使用合成凭据，不检查真实凭据内容。此过滤不承诺识别任意编码或源码中的所有秘密。
4. **历史读取资源没有上限**：旧版同时读取全部历史并保留完整证据，历史增加时可能耗尽文件描述符或内存。现在最多并行读取 8 项，逐批保留需要返回的最新记录。测试核对读取并发、最新顺序和损坏 JSON 的处理。仍会扫描历史，尚未引入持久索引。

## 验证范围

回归由 40 项扩展至 48 项，新增跨进程控制发布、失败写入、两类幂等竞争、转义凭据、嵌套 JSON、第二个 MCP 拒绝权限和有界历史读取。主要问题在旧实现上得到失败复现，再检查修复。类型检查、构建一致性与分发包继续验证。

真实模型复核已在后台和桌面两种模式通过：一个 MCP 进程启动真实 `sleep 30`，第二个进程取消该轮，再由第二个进程继续原会话。核对了两轮不同的所有者 PID、相同原生会话 ID、Flash / High 选择、控制消息全部消费，以及临时工作区没有文件改动。执行标识和本机界面证据另存本地验收目录，不随开源包分发。模拟测试中的权限选择不等同于原生桌面权限已被授权；桌面审批继续留在 Harness UI。

本次不增加远程执行、后台历史迁移或跨崩溃自动重放。P330/SSH 仍未实现；Windows、其他 Harness 版本仍需单独验证；中断锁回收标记和持续磁盘故障的处理边界见前版整体复查。
