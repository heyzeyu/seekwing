# 任务归属、能力差异和 Codex 显示：v0.4.2

## 工具继续统一，能力显式查询

SeekWing 保持一个 MCP 服务和一组任务工具，通过 `backend: deepseek | grok` 选择执行方。新增 `list_backends`，总计十个工具。等待、查询、续聊和取消通过持久任务记录选取后端，不要求 Codex 再猜一次。

| 已接入的能力 | DeepSeek | Grok |
| --- | --- | --- |
| 后台 ACP、持久会话、续聊 | 支持 | 支持 |
| 在原生界面实时显示 | Desktop 伴随插件模式 | 当前不连接已打开的 TUI；完成后可原生恢复会话 |
| 模型、推理档位 | 从自己的 catalog 读取 | 从自己的 catalog 读取，逐项核对配置结果 |
| 权限处理 | 后台由 SeekWing 转交；Desktop 留在 Harness | 后台由 SeekWing 转交 |
| 原生沙箱 | 后台配置覆盖；Desktop 会话预设 | macOS/Linux 原生 profile，发送指令前核对工作区和会话元数据 |
| 本插件的直接输入 | 文本指令 | 文本指令 |
| 图片、音频、单独调用原生搜索或子代理 | 没有独立接入 | 没有独立接入 |

能力表描述适配器合同。原生程序的插件、搜索、模型表现由版本、配置和账户决定；不能把 ACP 宣告的原生能力全部当作 SeekWing 已接入功能。`commandAvailable` 只表示发现可执行文件；`doctor` 才检查握手，握手也不证明登录或生成成功。

## 哪个 Codex 聊天派的任务

每个新运行记录增加：

- `title`：用户可读的任务名称。
- `origin`：最初派发聊天和来源方式，续聊保留。
- `submittedBy`：提交当前这一轮的聊天；另一聊天继续处理时也可追溯。
- `rootRunId`：新任务链的起始运行，和 `parentRunId` 一起关联后续轮次。

来源优先级：当前 MCP 请求中支持的聊天元数据 → 明确传入的真实 `callerThreadId` → MCP 进程的 `CODEX_THREAD_ID` / `CODEX_SESSION_ID` → 未知。只保存白名单归属字段，不保存全部请求元数据。元数据与显式参数矛盾时拒绝派发。宿主共享 MCP 进程时，环境变量可能属于启动时的聊天，应使用每次请求的身份，或从调用聊天读取 `CODEX_THREAD_ID` 后传入。

来源只是追溯信息和筛选条件，不是认证或跨用户隔离机制。本地状态目录仍由操作系统用户控制；不同聊天知道运行编号后，原有查询和控制能力保持不变。旧记录不补写猜测的归属；从未知旧记录续聊仍保留未知 origin，并记录这次的 submittedBy。旧链缺少 rootRunId 时只提供当前已知父节点，不能保证恢复完整历史链。

`list_tasks` 的 `scope: auto` 在身份已知时按 origin 选当前聊天，否则明确返回“全部本地任务，来源未识别”。`scope: current` 无身份时返回空列表及说明，绝不退回全局；`scope: all` 可查看旧记录。还支持 backend、status、rootRunId 筛选，先筛选再取最近 N 条，避免最近其他聊天任务把本聊天记录挤掉。按当前聊天筛选的是原始派发归属，不是 submittedBy；监督聊天查看既有任务时用明确 runId，或 all 加 rootRunId。

## 两种显示可以共存，但职责不同

### 当前聊天的卡片

按官方 MCP Apps 方式为任务工具声明 `_meta.ui.resourceUri`，注册自包含 HTML 资源，通过 `ui/initialize` 和 `tools/call` 与宿主交互。卡片显示标题、后端、来源聊天、权限、工作目录、原生会话、状态、分页输出和近期工具记录。活动卡片每秒只读刷新；隐藏时暂停，出错或结束后停止自动刷新。没有批准权限、派发新任务或调用模型的按钮。

卡片不需要部署网站或开放监听端口；仍返回 JSON 文本和 structuredContent，宿主不渲染 UI 时 Codex 可直接报告状态。completed 的文案是“执行结束 · 待核验”，不会把原生代理结束当成验收成功。

本机宿主安装包存在 MCP Apps HTML 资源与侧面板渲染实现，但公开文档对 UI 的部分说明面向 ChatGPT。协议与浏览器测试不能替代特定 Codex 聊天中的实际渲染验收。升级后需新开本地聊天加载新版工具，再检查卡片是否出现；本轮未把模拟宿主测试冒充 Codex App 内验收。

### 侧栏独立聊天

当前可行方案是宿主创建一个 **Codex 监督聊天**：Codex 在那个聊天内通过 SeekWing 派发给 Grok/DeepSeek、跟踪状态并核验。使用者在侧栏看到的是 Codex 监督聊天，其状态由 Codex 控制；Grok 的原生过程仍通过 SeekWing 卡片和运行记录呈现。这多消耗一层 Codex 推理，且依赖本地 MCP 进程存活，不是独立作业调度器。

本轮可用的宿主 `create_thread` 工具没有外部代理类型；原生子代理活动也是宿主专用记录。没有找到将任意 Grok/DeepSeek 会话注册成原生 Codex 子代理聊天的公开接口，不能承诺插件能直接实现这种效果。MCP Apps 的“侧栏应用入口”或“聊天侧面板”也不是侧栏子聊天。

Skill 已补充可选监督流程：只在用户明确要求创建聊天、且宿主提供工具时使用。已有任务先 get_task，不重新派发；新任务由监督聊天自行 start_task，其 origin 是监督聊天。不会通过写 Codex 数据库或伪造线程记录实现显示。本轮只检查和实现插件支持，没有创建额外聊天。

## v0.4.1 空白卡片与实时输出修复

旧卡片只监听 tool-result 且只读 structuredContent。等待工具运行期间，卡片即使已初始化，也可能还不知道 runId；此时刷新没有查询目标。新版监听完整 tool-input，从编号主动 get_task，不等 wait_task 结束；同时兼容 JSON 文本结果、预加载 toolInput/toolOutput 和 globals 更新。没有编号时提供手动绑定或当前聊天列表，不会猜选其他聊天的任务。

活动任务每秒读取本地已保存的输出和工具状态，不额外调用模型；这是轮询刷新，并非 token 级推送。默认 outputTail 读取最新窗口，避免输出超过第一页后看起来停止。用户可以切回较早页面或重新跟随最新。等待权限时继续观察状态，结束后停止轮询。输出只包含原生代理发出的可见文本和工具证据，思想片段仍不保存或展示。

新增版本化资源 tasks-v041.html，旧资源保留兼容；更新后需重开卡片加载新版。浏览器覆盖仅 tool-input（无 tool-result）、文本结果、globals 三种启动方式；原生 Codex MCP Apps 面板的最终显示仍需在加载新版的聊天中验证。

## v0.4.2 展开的实时执行日志

卡片直接展示原生代理的可见回复、实际命令、工具状态和文本结果，保留原始 JSON 作为可选证据。它只显示代理通过 ACP 发出的公开内容，不保存或展示思想片段。原生执行工具可能先返回后台句柄，随后继续发出 stdout 更新；工具返回不等于后台命令已退出。卡片仍按每秒读取一次的方式跟随更新，不承诺 token 级推送。

存储只保留近期 100 个工具调用，超过上限优先淘汰已结束记录，避免旧实现达到 100 次后停止显示新工具。前端保留已观察到的近期记录，查询窗口移动时也能连续查看，切换任务会清空前一任务日志。

真实 Grok 4.7 Fast / Low 只读联调：先显示 SW_LIVE_REPLY_BEGIN，再执行每隔 8 秒打印一行的 Python 命令。运行中分别在 19:27:02、19:27:10、19:27:18、19:27:26、19:27:34 观察到 stdout 1 至 5，任务直到 19:27:46 才结束，最后包含 SW_LIVE_REPLY_END。模型未读取项目文件，测试工作区没有新增文件。浏览器卡片在运行中实际显示了回复、命令和前两行 stdout，并保存截图。原生 Codex MCP Apps 面板仍需新聊天加载新版资源。
