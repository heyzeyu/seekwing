# v0.2.2 整体复查

日期：2026-10-20。基线：SeekWing `5ca00f7`（v0.2.1）。本次检查覆盖后台 ACP、桌面伴随插件、任务状态、权限和工作区、会话互斥、安装升级、诊断、关闭及分发文件。

## 修复结果

1. **旧会话锁并发回收**：两个进程可能根据同一份失效所有者记录先后删除锁，第二次删除会移除刚取得的有效锁。复现得到两个成功持有者。现在原子发布完整锁记录，串行回收并重新核对旧记录，保证只有一个持有者。回收期间崩溃遗留的标记不会被自动删除，避免再次引入相同竞态。
2. **证据持久化失败**：旧写入队列一旦失败，后续写入均被跳过；单纯发送取消不足以停止不响应的工作进程。现在写入队列可以恢复，存储故障触发有截止时间的取消和清理，最终状态包含 `persistenceError`。持续故障时保留内存结果并停止接收新任务；不把无法确认的清理当作成功，也不自动重放。最终持久化完成前，查询和列表均保持处理中状态，避免先报告完成再出现落盘错误。
3. **自定义端点与启动清理**：安装配置原先仅保留发现文件的目录，伴随插件固定写入 `endpoint.json`。现在完整传递文件路径；发布发现文件失败时会回收本次创建的本地监听器和 Host 订阅。
4. **不完整的安装包覆盖旧版**：原先逐个复制文件，后续文件缺失时已改写旧版入口。现在先读取校验全部源文件，再通过临时文件与原子重命名逐个替换，避免截断入口文件。不声称多文件更新具备跨崩溃事务保证。
5. **并行诊断互相删除配置**：同一 MCP 内的两个 ACP doctor 使用相同临时文件名；先结束的一次会删除另一次还没读取的配置。现在每次诊断使用独立随机标识。
6. **关闭期间迟到的任务**：工作区解析期间 MCP 可能已关闭，旧逻辑仍能接收该任务。现在在异步校验后、预留执行容量前重新检查关闭状态。

桌面 doctor 同时报告客户端 `version` 与正在运行的 `companionVersion`；版本不一致时给出安装和重启提示，避免只看到单个版本而误判更新已生效。

## 验证与边界

回归从 29 项扩充至 40 项。主要问题先通过故障注入和交错时序在旧逻辑复现，再验证修复；测试使用独立 ACP 线协议模拟器、本机 HTTP 和原生 Host 适配器。类型检查、构建一致性和分发文件也纳入验证。两种模式均已使用真实 DeepSeek Flash / High 验证生成、同会话续聊、实际修复代码及独立重跑测试、原生只读拒写；额外核对验收测试文件没有被修改。执行标识和本机截图另存为本地验收记录，不包含在开源包中。

运行环境仍以已验证的 macOS、Node 24.12.0、官方 Harness Desktop 0.2.1-rc.2 为准。Windows、其他 Harness 版本和 P330/SSH 需要单独适配与验证。Host 重启或提交结果不确定时不会自动重放；桌面审批仍在 Harness 完成；历史没有自动迁移或过期。持续磁盘故障不可能保证证据落盘，内存结果仅在当前进程存在时有效。
